# AI TV Studio — производственный режим для H3ZeroStudio

Разбор: что из списка требований уже есть в паке, что придётся строить и сколько это стоит.
Оценки в человеко-днях, без учёта времени на GPU-прогоны.

## 1. Зачем отдельный режим, а не набор галочек

Таймлайн H3ZeroStudio — про один ролик: отрезки, дубли, швы, ручная доводка. Телевизионный
контент для заведения — про **поток**: бренд, повторяющиеся лица и места, сценарий на минуты,
десятки независимых сцен, логотип в углу и часовой плейлист. Это другой жизненный цикл
(много проектов-сцен вместо одного проекта), поэтому нужен второй экран и второй набор
сущностей, но двигатель генерации переиспользуется целиком: сегменты, продолжение, кэш,
дубли, апскейл, маски, SAM 3.1, звук.

## 2. Что уже есть и переиспользуется

| Нужно для AI TV | Что есть в паке | Что доделать |
|---|---|---|
| Профили заведения | пресеты моделей, ассеты с категориями, темы интерфейса | сущность «бренд»: палитра, логотип, шрифт, CTA, стиль-префикс промпта, набор разрешённых персонажей/локаций |
| Библиотека персонажей и локаций | «Персонажи» — карточки RefMod (персонаж, локация, одежда, стиль, движение, голос) | превратить в самостоятельный каталог уровнем выше проекта: поиск, теги, привязка к бренду, «одна локация — много брендов» |
| Сценарий на 3/5/10 минут | LLM-ассистент промптов (`h3s_assist.js`, режимы ref2va/i2va/lipsync) | генератор сценария: биты с длительностями, раскладка по сетке H3 17k+5, лимит 124–362 кадра на отрезок, проверка сходимости суммы |
| Пакетная очередь независимых сцен | кэш по хэшу параметров, `/h3lab/status`, FIFO-очередь ComfyUI | раннер: N проектов-сцен из одного заказа, очередь с приоритетами, ретраи, отчёт «готово/упало» |
| Зацикленные видео | режимы по ключевым кадрам (первый/последний), футаж, апскейл | цикл как отдельный тип сцены: первый кадр = последний, стык по кроссфейду/оптическому потоку, автопроверка «шов цикла» |
| Логотипы и рекламные надписи | экспорт через ffmpeg, ассеты, `drawtext`/`overlay` доступны | встроенные оверлеи: роли ассетов (лого, титр, CTA), безопасные зоны, расписание показа, предпросмотр |
| Переиспользование нейтральных сцен | кэш, дубликаты проектов, zip-экспорт | библиотека шаблонов сцен + режим «рендер один раз, бренд сверху»; ключ кэша по шаблону, а не по бренду |
| Часовой плейлист | склейка сегментов, оценка швов, галерея | сущность «плейлист»: порядок, длительности, ротация, детерминированный shuffle, финальный concat, главы |
| Экспорт без звука | дорожки «Аудио»/«Музыка», `video_volume` | флаг `run.no_audio`: дорожку не писать вовсе (сейчас всегда есть, пусть и тихая) |
| Проверка повторов сцен | `h3s_diagnostics.clip_signature` (яркость/контраст/детали по сэмплам кадров) | перцептивный хэш кадров + отчёт «эта сцена ≈ та», порог, ручное «считать вариацией» |

## 3. Что построить

### 3.1 Данные (JSON рядом с проектами)
```
output/h3labstudio/
  _brands/<brand>.json          # палитра, логотип, шрифт, CTA, стиль, allowed_casts
  _library/casts/<id>.json      # персонаж: карточка RefMod + теги + привязки
  _library/scenes/<id>.json     # локация/шаблон сцены: промпт-скелет, fps, длительность, ассеты
  _scripts/<order>.json         # заказ: бренд, длина, темп, язык, число сцен
  _playlists/<id>.json          # порядок, ротация, оверлеи, экспорт-профиль
```
Сцены остаются обычными проектами (`_projects/<id>.json`) — значит работают кэш, дубли, апскейл
и повторный запуск через ту же ноду `ZL_H3ZeroStudioLab`. Это ключевое решение: **новый режим не
дублирует движок, а оркестрирует проекты**.

### 3.2 Пайплайн заказа
1. **Сценарий.** LLM-ассистент → бит-лист: `{scene_id, длительность, каст, локация, действие, реплики}`.
   Валидатор режет биты по 17k+5 и по обучающему диапазону 124–362 кадра (5–15 с), проверяет сумму = заказанные 3/5/10 мин.
2. **Пакет.** Каждый бит → проект-сцена (ref2va, каст из библиотеки, локация из шаблона), общий seed-политика, единый пресет модели.
3. **Очередь.** Раннер отправляет промпты в ComfyUI (как это уже делает bench-harness), следит за `/h3lab/status`, ретраит упавшее, пишет отчёт.
4. **Сборка.** Склейка сцен одного бренда → оверлеи лого/CTA → при необходимости цикл → плейлист на час.
5. **Контроль.** Отчёт: дубликаты сцен, швы, длительности, отклонения от сценария, стоимость в GPU-минутах.

### 3.3 Оверлеи и цикл (технически простое)
- Оверлеи — фильтры ffmpeg поверх готового MP4: `overlay` для лого (позиция, отступ, прозрачность, fade in/out), `drawtext` для CTA (шрифт из бренд-профиля, безопасная зона, расписание показа по таймкоду). Рендер не пересчитывается.
- Цикл — сцена типа «loop»: финальный кадр пинуется равным первому (режим по ключевым кадрам уже есть), плюс проверка стыка (оптический поток/кроссфейд 6–12 кадров) и метрика «скачок на стыке».

### 3.4 Проверка повторов
`clip_signature` даёт цвет/контраст/детали. Добавить dHash по 3–5 кадрам сцены + сравнение текста промпта
(нормализация, шинглы) → отчёт «сцена 12 ≈ сцена 4 (0.94)». Порог настраиваемый, вариации бренда не считаются повтором.

## 4. Оценка работ

| Блок | Дни | Комментарий |
|---|---:|---|
| Бренд-профили | 3–4 | JSON + UI-вкладка + подстановка в промпт и оверлеи |
| Каталог персонажей/локаций уровня «студии» | 2–3 | карточки есть, нужен каталог и связи с брендом |
| Сценарий 3/5/10 мин | 4–6 | бит-лист, валидатор сетки H3, длительности, реплики |
| Пакетная очередь сцен | 3–4 | раннер, статусы, ретраи, отчёт |
| Циклы | 2–3 | тип сцены + проверка стыка |
| Оверлеи (лого/CTA) | 2–3 | ffmpeg-фильтры, безопасные зоны, предпросмотр |
| Библиотека нейтральных сцен | 2–3 | шаблоны + «один рендер — много брендов» |
| Плейлисты на час | 3–4 | сущность, ротация, concat, главы |
| Экспорт без звука | 0,5–1 | флаг в run-опциях + тесты |
| Проверка повторов | 2–3 | dHash + текстовый похожий поиск + отчёт |
| **Итого** | **24–34** | |

MVP (бренд, очередь сцен, оверлеи, экспорт без звука, простой сценарий на 3 мин): **9–12 дней**.

## 5. Ограничения и риски

- **Сегмент H3 = 5–15 секунд.** 10-минутная программа — это ~40 отрезков по 15 с (или 15 по 40 с на верхней границе 957 кадров). Дрейф внешности на длинной цепочке неизбежен: нужен «якорь» — периодический возврат к кадру-эталону персонажа и проверка `clip_signature` по ходу.
- **Стоимость времени.** Замер на локальной карте: 10-секундный клип 1344×768 pi-H3 — 4–4,5 мин (pi2 ~3,9 мин). Программа на 10 минут ⇒ **3,5–4,5 часа GPU**, плейлист на час ⇒ **20–28 часов**. Для потока это значит ночные окна и/или черновое разрешение (0,5 Мп) как стандарт.
- **Диск.** 1,25 МБ/с при 1344×768 ⇒ 10 мин ≈ 750 МБ, час ≈ 4,5 ГБ на программу; ротация и автоочистка обязательны.
- **Музыка.** Локальный генератор подложек в H3 не является лицензированным каталогом: для заведения дорожку нужно фиксировать через lane «Аудио» из своего файла.
- **Логотип и реклама.** Оверлей обязан быть вне генерации: перегенерация сцены не должна менять лого, а CTA-текст не должен попадать в промпт (иначе модель читает его вслух — уже наблюдалось).
- **Повторы.** Полностью детерминированная ротация без повторов на час требует библиотеки ≥ 40–60 сцен; иначе повтор неизбежен и должен быть «легальным» (смена бренда/оверлея).

## 6. Что можно сделать сразу, не строя новый режим

- Флаг «экспорт без звука» — 1 день, полезно и вне студии.
- Библиотека шаблонов сцен + «один рендер — много брендов» — использует существующий кэш.
- Скрипт-раннер пакетной очереди на базе ноды (как в bench-harness) — уже проверенный путь: N проектов-сцен, проверка и отчёт.
